# Draft Room: architecture and build plan

A live snake-draft tool for the September draft, built into this app, whose result rolls straight into the
dashboard. Design reference: the Claude Design handoff (`Boxscore_drafting_interface.zip`, "The Draft Room").
This doc is the plan; it is not yet implemented.

## Decisions made

- **Handoff:** an export script writes the finished draft into a new season file, which is reviewed and
  committed. No runtime loading of results from the worker.
- **Identity:** trust plus undo. Drafters are whoever `js/identity.js` says (same tier as chat/favorites);
  the commissioner can undo or edit any pick. Commissioner actions use the existing `ADMIN_PASSWORD`
  (`isAuthorized` in `worker/rundown-proxy.js`).
- **Seasons:** the app must hold two draft classes at once (see below), so it is season-ized *before* the
  draft room is built.
- **Frontend:** vanilla ES modules, no framework or build step, matching the repo. The handoff's
  React suggestion is not followed.

## Why seasons come first

A draft class spans several real seasons. The 2026 class covers NFL/CFB '26, EPL/NBA/NHL/CBB '26/27 and
MLB/WNBA '27. The next draft (September 2027) covers NFL/CFB '27, EPL/NBA/NHL/CBB '27/28 and MLB/WNBA '28.
In fall 2027 both classes are live: the 2026 class still has MLB and WNBA running, and the 2027 class's
MLB/WNBA sit in the same "prior-season, non-scoring" state as today's `PRIOR_SEASON_DISPLAY_LEAGUES`.

### Season model

- Each class is a file: `js/seasons/2026.js` (today's data, moved as-is) and later `js/seasons/2027.js`
  (generated by the draft export). Each holds `TEAM_META`, `LEAGUES`, `LEAGUE_SCORING` and its
  prior-season league list.
- `js/data.js` keeps `DRAFT_TEAMS` and re-exports `TEAM_META`, `LEAGUES`, `LEAGUE_SCORING` and
  `PRIOR_SEASON_DISPLAY_LEAGUES` from the active class, chosen once at boot from `?season=` or the saved
  setting. Consumers (about 250 references across 22 files) do not change. Switching season reloads.
- A season switcher (Settings, Points header) defaults to the newest class. Points totals are per class.
- **Storage is namespaced by season.** Worker KV (`facts:<league>`, `favorites:<drafter>`, season locks)
  becomes `facts:<season>:<league>` etc., and client caches keyed by team id or league gain the season.
  Legacy un-namespaced keys are read as the 2026 class, so nothing needs migrating.
- **Finished leagues are frozen.** ESPN only serves the season being played, so an old class's standings
  cannot be rebuilt live once a league moves on. The season lock (`js/season-lock.js`) is extended to
  snapshot the final standings table and points; finished leagues render from it with a "Final" badge.
  Leagues still running keep pulling live data. Minimum viable version: old classes show rosters and final
  points only.

## Draft room architecture

**Backend: `DraftRoom` Durable Object** (`worker/draft-room.js`), modeled on `worker/chat-room.js`:
SQLite storage, WebSocket Hibernation, one room reached at `/draft/ws`, room id parameterised so mock
drafts can run on a throwaway room.

- Owns phase (`lobby | draft | done`), lottery order, picks, trade overrides, write-in teams, clock
  start/pause, and each drafter's queue (server-side so it follows you across devices).
- Soft clock, no auto-pick, so no alarms: clients render the countdown from a server timestamp.
- Server validates every pick: correct owner (or commissioner), team not taken, league cap not exceeded,
  not paused.
- Reconnect resumes with `?after=<lastPickId>`; first frame is a full state snapshot.
- Deploy the worker before the static site (new `[[migrations]]` entry for `DraftRoom`).

**Shared rules: `js/draft-rules.js`**, pure code for snake order, `ownerOf(slot)`, caps and "does this
pick fit", imported by both the client and the worker instead of duplicated. Needs a spike to confirm
wrangler bundles an import from outside `worker/`; fallback is a copy plus a consistency check.

**Frontend:** a new `#view-draft` at `?view=draft` via `switchView`; files `js/draft.js`,
`js/draft-board.js`, `js/draft-pool.js`, `js/draft-mobile.js`. Desktop is the 3-column layout; phone is
Pick / Board / My team tabs. The design's dark-only tokens map onto the existing CSS variables so the
light theme works.

### As built (Phase C)

- `js/draft-rules.js` (pure helpers: snake order, slot ownership, caps, clock math) and
  `js/draft-engine.js` (one pure `reduce(state, action, ctx)` state machine) have no imports beyond each
  other, so the client, the worker and Node tests all use the same code. Tests:
  `node --test tests/draft-engine.test.mjs` (includes 30 random full-size 210-pick drafts asserting nobody
  is ever stuck and every roster lands exactly on its caps).
- `worker/draft-room.js` is the `DraftRoom` Durable Object (bound as `DRAFT_ROOM`, migration `v2`),
  reached at `/draft/ws?room=<name>`; `GET /draft/result?room=<name>` returns the finished board.
  Confirmed that wrangler bundles the shared `../js/` files. `tests/draft-room.integration.mjs` drives a
  running `wrangler dev --var ADMIN_PASSWORD:testpw` end to end.
- Differences from the sketch above: every accepted action broadcasts the **whole** (small) state instead
  of deltas, so there is no `?after=` resume (a reconnect just gets a fresh `hello`); the commissioner
  authenticates with an `auth` frame (a browser WebSocket can't send the admin header); the team pool is
  uploaded by the commissioner in the lobby (`setPool`) so the server can validate picks; an append-only
  `events` table records every accepted action for disputes.

### As built (Phase D)

- `js/draft-client.js` (socket + store: reconnect, acks, server-clock offset, commissioner auth),
  `js/draft-pool.js` (pool from the active season's `TEAM_META` ranked by `js/draft-ranks.js`, the design's
  consensus order), and `js/draft.js` (the view). Reached from Settings -> Draft room or `?view=draft`
  (`&room=<name>` for a rehearsal room); the socket only opens while the view is on screen.
- Built: lobby (order card with the bottom-up lottery reveal, commissioner sign-in, Load team pool, clock
  length, Run lottery, Start draft), and the live room (Available pool with search, league chips, top-60
  toggle, Draft -> Confirm, star queue and write-in card; on-the-clock card with soft clock; up-next strip;
  the snake board; My roster and My queue with top-fit Draft). Under 1180px the roster/queue column shares
  the left slot behind tabs; under 700px it stacks. Rank in the pool is *within league*; the All list
  interleaves leagues by rank percentile.
- Not yet (Phase E): pause/undo/reset/edit-a-pick/trade controls and pick-for-someone in the live room, and
  the proper phone layout (Pick / Board / My team tabs).
- Verified end to end against `wrangler dev`: a scripted room drafted all 210 picks through the real UI,
  the write-in flow and Draft -> Confirm worked, and the finished roster landed exactly on its caps.

### Rules (from the design)

10 drafters, 21 rounds, 210 picks, snake order set by a random lottery. Caps per drafter sum to 21:
EPL 2, NFL 3, NBA 3, NHL 3, MLB 3, WNBA 1, CFB 3, CBB 3. A team can be drafted once. Draft then Confirm
within 3.5s. Commissioner: run lottery, pause/resume, undo, reset, pick for the on-clock drafter, edit
any past pick (creating a make-up slot), trade picks (the prototype has the modal but no entry button).

### Team pool

The design's `draft-data.js` has only abbreviation, name and color, which is not enough for live data.

- Pro leagues: build the pool from the active season's `TEAM_META`, deduplicated by league and name with
  the owner stripped, so real `espnTeamId`, `sportsdbId`, `rundownTeamId` and `badgeUrl` carry over. The
  design's consensus ordering is used only for rank.
- CFB/CBB: preload roughly the top 40 each; everything else is a write-in.
- Write-ins must be resolved against ESPN's team list server-side to get an `espnTeamId` and logo,
  otherwise the team has no live data for the whole season.
- A small yearly config covers EPL promotion/relegation and WNBA expansion.

### Export

`tools/export-draft.mjs` pulls the frozen draft result (210 picks) and writes a new
`js/seasons/<year>.js`, generating team ids in the existing `owner_slug` convention (with a `_cbb` style
suffix on same-owner cross-league collisions) and `LEAGUES` arrays in pick order. Output is reviewed as a
diff and committed; Cloudflare Pages deploys it. A bad export cannot break the running season because it
only adds a file.

## Build order

| Phase | Ships |
|---|---|
| **A. Seasonize** | Move current data to `seasons/2026.js`; resolver in `data.js`; season-keyed storage; switcher. No visible change; this is the regression check. |
| **B. Freeze support** | Extend the lock to snapshot final standings and points; old classes render from it. |
| **C. Draft engine** | Spike worker import of `draft-rules.js`; `draft-rules.js` with Node tests; `DraftRoom` with protocol, persistence, reconnect. |
| **D. Draft UI** | Lobby, board grid, on-the-clock card, pool, search, league chips, Draft/Confirm, roster, queue, write-ins. |
| **E. Commissioner and mobile** | Lottery, pause, undo, edit a pick, trades, phone tabs. |
| **F. Export** | `export-draft.mjs` and the write-in to ESPN-id resolver. |
| **G. Dress rehearsal** | Full mock drafts on a throwaway room id, including running the export. Draft day cannot be redone. |

Extra: when a drafter goes on the clock, the room posts a system message into the existing chat as a free
notification channel.
